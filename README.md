# Saturnita Pulse

В кабинете доступны короткие ссылки, статистика переходов, домены, веб-аналитика и HTTP-мониторинг сайтов, API и целей ссылок. В разделе «Мониторинг» видны доступность, задержки, результаты проверок и инциденты. [Сценарии ссылок и аналитики](docs/local-links-analytics.md) · [Мониторинг, демоданные, развёртывание и восстановление](docs/production.md) · [Контракт API](openapi/product.json).

Этапы 2–4 включают локальный запуск, дизайн-систему, кабинет и управление учётной записью. Подробный план проекта находится в [docs](docs/README.md).

## Запуск

Из корня выполните `docker compose up -d --build` и откройте http://localhost:5173. На Windows также подходит `docker-compose`. Одноразовый сервис migrate применяет версионированную миграцию перед запуском API. PostgreSQL хранит данные в томе pulse-data. Для остановки используйте `docker compose down`. Параметры локальной среды перечислены в .env.example. Порт по умолчанию привязан к loopback. Для смены порта задайте APP_PORT перед запуском. Пример пароля БД предназначен для локальной разработки.

Создайте аккаунт, откройте «Настройки», измените имя и перезагрузите страницу. Смена пароля отзывает другие входы. Текущую сессию можно завершить в настройках или кнопкой «Выйти». Для изменений API ожидает Origin приложения и заголовок X-CSRF-Token из GET /api/v1/me. Пароль содержит минимум 12 символов, максимум 256 байт. Сессия действует 14 дней.

Overview показывает переходы за семь дней и текущее число ссылок и сайтов. Для просмотра макета с данными установите `VITE_DEMO_MODE=true` в корневом .env и пересоберите frontend. Адрес демонстрации — /demo. Для проверки готовности доступны /healthz и /readyz.

## Проверки

Действующий контракт кабинета находится в [openapi/identity.json](openapi/identity.json). Команда `npm run api:types` в frontend обновляет типы клиента. В docs/openapi.json сохранён проект API последующих этапов.

В backend запустите `go test ./...` и `go vet ./...`. Интеграционный тест использует TEST_DATABASE_URL отдельной тестовой PostgreSQL с применённой миграцией. На Linux доступна проверка `go test -race ./...`. Чтобы откатить миграцию **в пустой тестовой БД**, используйте CLI golang-migrate с каталогом backend/migrations и командой down 1. Команда откатывает последнюю применённую версию и удаляет её данные.

В frontend выполните `npm ci`, `npm run lint`, `npm run typecheck` и `npm run build`. Для сценария регистрации в браузере запустите локальный тестовый стек, затем `npx playwright install chromium` и `npm test`. Тест создаёт отдельные аккаунты. CI проверяет сборку образов, реальную PostgreSQL и браузер в двух размерах экрана.
