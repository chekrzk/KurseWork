# Ссылки, домены и события сайтов

Откройте кабинет на http://localhost:5173. В разделе «Ссылки» задайте название и целевой URL. Пустой slug генерируется сервером. Для системного домена приложение возвращает адрес вида http://go.localhost:5173/promo. Зарегистрируйте свободное имя в «Домены», чтобы получить такой же маршрут на персональном поддомене. Браузер должен разрешать *.localhost в loopback. Для проверки через curl подходит параметр `--resolve go.localhost:5173:127.0.0.1`.

Переход GET возвращает 302 после фиксации клика и счётчика в одной транзакции. HEAD проверяет доступность ссылки без записи события. Истечение срока, архивирование и исчерпание лимита дают 410. Архив сохраняет отчёт. Для удаления истории откройте архивную ссылку и подтвердите окончательное удаление. Настроенные UTM замещают соответствующие ключи в целевом query. Остальные пары, повторы и fragment сохраняются.

В «Аналитике» выберите период. Приблизительные уникальные посетители — сумма дневных количеств различных HMAC по UTC. Для общего отчёта ключ привязан к владельцу ссылок, для сайта — к сайту. IP и User-Agent обрабатываются в памяти. База хранит дневной псевдоним и категории устройства. GeoIP опционален и на локальном стенде отключён. События старше 180 дней удаляются пакетами. Счётчик лимита ссылки учитывает весь срок её жизни.

## Подключение tracker.js

В «Сайтах» укажите имя, домен, часовой пояс и точные разрешённые origins с портами. Вставьте выданный script в HTML. Скрипт отправляет pageview, отслеживает изменение URL в SPA и поддерживает `window.Saturnita.track("signup_completed", {plan:"free"})`. Передавайте в свойствах только неперсональные данные. Сбор использует fetch с keepalive и credentials=omit. Сервер сверяет Origin и public ID, проверяет размер, давность и структуру события. Публичный идентификатор сайта виден посетителям.

Для локальной демонстрации укажите домен localhost и origin http://localhost:5173. Откройте /tracker-demo.html?site_id=PUBLIC_ID на этом origin. Обновление страницы добавит просмотр, кнопка отправит demo_click. В отчёте сайта появятся реальные события. Браузерный автотест также подключает tracker с отдельного HTTP-сервера на другом порту.

## Внешний домен и HTTPS

Заявка для go.company.ru выдаёт случайное значение TXT для _saturnita.go.company.ru на 24 часа. «Проверить TXT» переводит заявку в verified. Для активации проверяются TXT повторно и каноническое имя CNAME go.saturnita.ru. Сменить challenge можно в кабинете. Ошибки DNS оставляют домен недоступным для ссылок. Интеграционный тест проверяет весь путь с управляемыми DNS-ответами без изменения публичных записей.

На будущем сервере нужны apex и wildcard DNS, доступные 80/443 и постоянное хранилище Caddy. Для *.saturnita.ru потребуется wildcard-сертификат через DNS-01, подходящий модуль DNS-провайдера и ограниченные credentials. Для внешних доменов применяется on-demand TLS. Во внутренней сети задайте Caddy `on_demand_tls { ask http://backend:8080/internal/caddy/allow-domain }` (директива ask на отдельной строке), а в catch-all HTTPS блоке — `tls { on_demand }`. Backend разрешает только active custom hostname. На публичном edge заблокируйте /internal/* до маршрутизации, передавайте исходный Host и устанавливайте X-Pulse-IP из адреса соединения. Backend и БД должны быть доступны только по внутренней сети. На локальном стенде Caddy обслуживает HTTP. Официальное описание выпуска сертификатов: [Caddy Automatic HTTPS](https://caddyserver.com/docs/automatic-https#on-demand-tls).

Для размещения за пределами localhost задайте отдельный случайный ANALYTICS_MASTER_KEY длиной от 32 байт, общий для экземпляров приложения. Для localhost используется сгенерированный при миграции ключ в служебной таблице. PULSE_EDGE=caddy разрешает доверять заголовку X-Pulse-IP только в топологии с изолированным backend и перезаписью заголовка на ingress.
